# 醉龙酒馆：龙誓

一款仿《博德之门 3》的单人文字跑团游戏。你在 AI 说书人的主持下自由行动：说服、欺骗、战斗、招募同伴，也可以和同伴恋爱。规则是简化的 D&D 5e，关键时刻掷 d20。

> 一条垂死的银龙在暴风雨夜坠入港口，她的“龙誓”碎成七片，烙在了七个人的掌心。你是其中之一。

## 文件

- `index.html`：游戏本体，单文件，无需构建。
- `docs/剧本设定集.md`：完整的世界观、系统规则、角色卡（含立绘提示词）、分幕剧本、结局条件和 AI 说书人提示词。
- `HANDOFF.md`：交接文档，接手时先看这个。
- `portraits/`：角色立绘，命名为 `角色id_表情.webp`，例如 `selene_neutral.webp`（768×1152，由 GPT 生成的 1024×1536 原图压缩而来）。缺图时游戏会显示占位剪影。

## 怎么玩

本机自用可以直接双击 `开始游玩.cmd`，打开 `http://127.0.0.1:8787/`，在设置里选择 **ChatGPT（本机）**。它使用本机 Codex 已登录的 ChatGPT 账号和套餐额度，不需要填写 API Key；需要 Node.js、Codex 和网络。以后如登录失效，先在 Codex 中重新登录 ChatGPT，再点游戏设置里的“重新检查”。

**省额度**：账号默认的往往是最强也最费额度的模型。在设置里可以分别选“说书人模型”（每一轮剧情用）和“整理记忆用的模型”（后台写前情提要和章节纪要，选最省的就够），选择会记住，不改动 Codex 本身的默认设置。

**用 API 玩**：同样从 `开始游玩.cmd` 打开，在设置里换成“OpenAI 兼容 API”，填接口地址、模型名和密钥即可，存档照样写硬盘、和本机 ChatGPT 模式是同一份。直接双击 `index.html` 也能用 API，但存档只在浏览器里。

说书人有三种接法，在游戏的 **设置 → 说书人接口** 里切换：

1. **Claude（claude.ai 内）**：在 claude.ai 以 Artifact 打开时，游戏通过 `sample` 能力调用 Claude，消耗你自己的 Claude 额度，不需要密钥。
2. **OpenAI 兼容 API**：用浏览器直接打开 `index.html`，或部署到 GitHub Pages 后，填入接口地址、模型名和 API 密钥即可。GPT、DeepSeek、Kimi 等兼容 `/chat/completions` 的服务都可以用。密钥只保存在你自己的浏览器里。
3. **ChatGPT（本机）**：从 `开始游玩.cmd` 打开的本机页面使用；账号授权由本机 Codex 管理，网页不接触账号令牌。此模式消耗账号套餐额度，不是离线模型。

本机模式的存档写在硬盘的 `.dragon-oath-local/saves/` 里（浏览器里另有一份副本），换浏览器、清理浏览器数据都不会丢，覆盖前还会自动留历史备份。claude.ai 和直接打开文件时，存档只在浏览器里。不同入口之间、换电脑时，用存档菜单里的“导出当前进度”和“从文件导入”搬存档。详细接入与实测范围见 `HANDOFF.md` 的“本机 ChatGPT 接入”。

开启 GitHub Pages：仓库 Settings → Pages → Source 选 `main` 分支根目录，保存后就能通过 `https://<用户名>.github.io/dragon-oath/` 访问。

## 给后续开发者

整个游戏是 `index.html` 一个文件，原生 JS，不用构建，也没有依赖。开发前先读 `docs/剧本设定集.md`，所有剧情和数值都以它为准。

核心原则：**代码管数字，AI 管故事**。AI 每轮返回“叙述正文 + `@@@` + JSON 变更请求”，由 `applyGM()` 校验后才生效（赞同度单轮 ±15、金币 ±50、标记只接受 `FLAG_KEYS` 里的键等）。

| 代码位置 | 作用 |
| --- | --- |
| `RACES` `CLASSES` `BACKGROUNDS` `SKILLS` | 角色创建数据。仿 BG3：选职业时 `classPreset()` 套用该职业的推荐属性（`CLASSES[x].base`，都是 27 点）；种族加值 +2/+1 由玩家自选（`draft.bonus`，默认放在 `CLASSES[x].prime` 两项），种族只决定特性；背景只给技能 |
| `COMPANIONS` `PEOPLE` | 同伴角色卡与立绘 id |
| `SCENES` `SCENE_ORDER` | 场景锚点：每场必然发生什么、何时推进到下一场 |
| `FLAG_KEYS` | 允许写入的世界状态标记及取值 |
| `SYSTEM` `buildPrompt()` | 说书人提示词与每轮上下文 |
| `narrate()` | 说书人接口：换模型只改这里 |
| `applyGM()` | 校验并执行 AI 的 JSON |
| `openDice()` `finishRoll()` | d20 检定 |
| `KITS` `FEATS` `ENEMIES` `ENCOUNTERS` | 战斗数据：职业武器与特技、敌人数值、遭遇（区域、敌人、事件） |
| `startCombat()` `advanceCombat()` `endCombat()` | 区域制回合战斗：开战、回合循环、结算 |
| `foeTurn()` `allyTurn()` | 敌人和同伴的自动行动 |
| `applyCombatFx()` `combatBrief()` | 即兴行动效果的校验执行、给说书人的战况 |
| `renderCombat()` | 战斗面板 |
| `recentLines()` `remember()` `summarize()` | 记忆：最近剧情原文、角色记忆、后台整理前情提要 |
| `levelUp()` `growth()` `applyAsi()` | 等级：里程碑升级、职业随等级成长、属性提升 |
| `ROMANCE` `CAMP_EVENTS` `applyBonds()` | 恋爱阶段、营地夜谈的处境素材、恋爱/关系/补给字段的校验 |
| `enterCamp()` `talkTo()` `restNight()` `renderCamp()` | 营地：扎营、找人夜谈、睡觉长休与共度一夜、营地面板 |

加新的一幕：在 `SCENES` 里追加场景、在 `FLAG_KEYS` 里登记新标记、在 `COMPANIONS` 里加新同伴，然后把上一幕最后一场的 `next` 指向新场景。需要升级的场景写上 `level: n`（进入这一场时全队升到 n 级）。

### 等级怎么运作

- **里程碑升级**：不攒经验。场景数据写 `level: n`，进入这一场时 `levelUp(n)` 让全队升到 n 级；序幕“第一个梦”是 2 级。同伴始终和玩家同级（`state.player.level` 就是全队等级）。旧存档读档时 `catchUpLevel()` 按走过的场景补级。
- **每升一级**：生命上限 + 生命骰一半 + 1 + 体质调整值（取平均，不掷骰），全队回满。熟练加值 1–4 级 +2、5–8 级 +3、9–12 级 +4，影响检定和攻击。
- **属性提升**（4、8、12 级）：玩家在弹窗里给一项 +2 或两项各 +1（单项最高 20），体质调整值变化会按等级补生命上限；没分配完时选项里一直有提醒。同伴自动给主属性 +2，存在 `state.companions[id].ab`，读取属性统一用 `abOf()`。
- **职业成长**（`growth()`）：偷袭每 2 级 +1d6；戏法 5 级起伤害骰翻倍；魔法飞弹、治疗之语、至圣斩每 2 级多一次，其他特技 5 级多一次；战士、圣武士、游荡者 5 级“额外攻击”（玩家攻击后还能再攻击一次，同伴自动打两次）；法师 5 级学会火球术（选一个区域，里面所有人 8d6 火焰伤害，敏捷豁免减半，同伴也会被烧）。
- 敌人不随等级变化，每场遭遇按设计等级写数值。

### 营地与恋爱怎么运作

原则是**自由优先**：台词和情节全交给说书人，代码只守几条底线。

- **扎营**：战斗之外选“扎营休息”（消耗 1 份补给，`state.supplies`，新游戏 2 份；说书人可用 `supplies` 字段加减），或说书人在玩家想睡觉时写 `"camp": true`。场景可以写 `camp: false`（不能扎营）、`campFree: true`（不耗补给，比如序幕的酒馆）、`campNext`（睡醒后进入这一场）。序幕“余烬”打完仗睡觉时，先在壁炉边度过一夜，睡下后进入“第一个梦”。
- **夜谈**：营地面板列出在营地的同伴。`planNight()` 每晚按“主线 > 恋爱 > 个人任务 > 友情”挑一个事件，对应的同伴标“！”；同伴之间的群戏（`kind: "banter"`）另外列成按钮。事件（`CAMP_EVENTS`）只写**处境和可用的素材**，说书人可以不用，玩家也可以把话题岔开。说书人写 `talk_end` 或玩家点“结束谈话”就回到篝火边。营地里不推进主线、不开战。
- **恋爱**：阶段 `none → hint（暧昧）→ together（恋人）→ vowed（誓约）`，说书人用 `romance` 字段推进，**营地内外都可以**。代码只管：一次一格；赞同度门槛 40 / 60 / 80；誓约要先通过个人任务考验（`c.tested`，个人任务还没做）；角色底线 `ROMANCE_RULES`（赛勒涅被发现撒谎就不接受；各人接受多人恋爱需要的赞同度）。分手写 `to: "none"`。
- **多人恋爱**：已有恋人时和别人走到恋人，这段关系自动记为秘密（`secret`）。现任会通过营地事件找你谈，用 `consent` 表态：同意后不再是秘密，不同意赞同度 −15。秘密恋情在其他恋人也在营地的夜里有三分之一的机会败露：所有恋人赞同度 −25，并记进角色记忆。
- **睡觉**：长休全员回满、天数 +1。有恋人在营地时可以选“和谁一起睡”，说书人写这一夜的亲密（到最亲密那一步用转场带过）和第二天清晨。
- **同伴之间**：`state.rel` 记两两关系值，说书人用 `relation` 字段调整（每次最多 ±10），提示词里会带上。
- **亲密的尺度**写在 `SYSTEM` 里：随关系阶段递进，双方都可以拒绝，每个同伴的方式不同。

加新的战斗：在 `ENCOUNTERS` 里写区域（`adj` 是相邻区域下标，`tags` 可用 `cover` 掩体、`high` 高处、`obscured` 遮蔽、`exit` 出口）、敌人和回合事件，新敌人加进 `ENEMIES`，再把遭遇 id 写进对应场景的 `encounters`。说书人只能开启当前场景登记过的遭遇。

### 战斗怎么运作

- 说书人在 JSON 里写 `"combat":"遭遇 id"` 开战。之后代码接管：先攻、移动、攻击、伤害、倒地与死亡豁免、借机攻击，以及敌人和同伴的行动。
- 玩家每回合有动作、附赠动作、移动各一次，在区域图上点选。自由输入框变成“即兴行动”：说书人裁定，可以先要求检定，再用 `combat` 字段给出伤害、状态、点火或敌人投降，由 `applyCombatFx()` 校验（单次最多 4d12、目标必须在场）。
- 轮到玩家前，说书人把这段时间的战况写成一段描写（设置里可改成“只在关键时刻”）。战斗结束时，代码把结果摘要发给说书人，由它接着讲故事、推进场景。
- 遭遇的 `lethal: false` 表示不会死人：死亡豁免失败三次只会昏迷。

### 记忆怎么运作

每一轮都是一次独立的请求，提示词从存档重新拼出来，不会越聊越长。为了让角色记得更早的事，记忆分五部分，都存在 `state.memory` 里：

- **最近剧情**：还没压缩的原文，最多约 1.2 万字。战斗流水账不算在内（只在战斗中附带最近 10 条），战斗结束后由一条结果摘要代替。
- **往事**（`memory.chapters`）：每条记录都带场景标记 `s`。一个场景结束后，`writeChapter()` 在后台读这一场的全部原文，写一份 250–400 字的章节纪要，写好就不再改，所以早期细节不会在反复改写中走样。旧存档会按记录里的章节标题补上场景标记，并每轮补写一章。
- **前情提要**：原文攒到 1 万字时，`summarize()` 在后台把较早的部分（只留最近 5000 字原文）交给 AI 压缩进提要，被压缩的条目打上 `m` 标记。提要只管往事还没覆盖的部分，往事写好后会自动瘦身。
- **角色记忆**：每人最多 10 条“关于你的事”。说书人遇到承诺、谎言、恩情、亲密时刻等，用 JSON 的 `remember` 字段当场记下，屏幕提示“某某会记住这件事”；整理提要时 AI 会合并去重。玩家可以在日志和同伴的角色卡里看到。
- **想起的旧事**：`recallLines()` 把玩家这句话切成 2–4 字的片段，在已压缩（`m`）的旧原文里查找，越少见的片段权重越高、人名加倍，取最相关的 3 段（连同当时玩家说的话，最多 2500 字）交给说书人。纯文本匹配，不调用模型。

后台的章节纪要和前情提要排成一队依次执行（`queueMem()`）。本机 ChatGPT 一次只接一个请求，所以这个模式下玩家行动会先等队里的任务做完。

阈值在 `RECENT_CHARS` `SUM_AT` `SUM_KEEP` `CHAPTER_SRC` `RECALL_CHARS` `RECALL_MIN` 几个常量里，调大能记得更多原文，但每轮更费额度。往事每章约 400 字，三幕全部写完大约 1 万字；到时可以考虑把一整幕的纪要再合并成一段。
