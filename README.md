# 醉龙酒馆：龙誓

一款仿《博德之门 3》的单人文字跑团游戏。你在 AI 说书人的主持下自由行动：说服、欺骗、战斗、招募同伴，也可以和同伴恋爱。规则是简化的 D&D 5e，关键时刻掷 d20。

> 一条垂死的银龙在暴风雨夜坠入港口，她的“龙誓”碎成七片，烙在了七个人的掌心。你是其中之一。

## 文件

- `index.html`：游戏本体，单文件，无需构建。
- `docs/剧本设定集.md`：完整的世界观、系统规则、角色卡（含立绘提示词）、分幕剧本、结局条件和 AI 说书人提示词。
- `HANDOFF.md`：交接文档，接手时先看这个。
- `portraits/`：角色立绘，命名为 `角色id_表情.webp`，例如 `selene_neutral.webp`（768×1152，由 GPT 生成的 1024×1536 原图压缩而来）。缺图时游戏会显示占位剪影。

## 怎么玩

本机自用可以直接双击 `开始游玩.cmd`，打开 `http://127.0.0.1:8787/`，在设置里选择 **ChatGPT（本机）**。它使用本机 Codex 已登录的 ChatGPT 账号和套餐额度，不需要填写 API Key；需要 Node.js、Codex 和网络。以后如登录失效，先在 Codex 中重新登录 ChatGPT，再点游戏设置里的“重新检查”。

**省额度**：账号默认的往往是最强也最费额度的模型。在设置里可以分别选“说书人模型”（每一轮剧情用）和“整理记忆用的模型”（后台写前情提要和章节纪要，选最省的就够），选择会记住，不改动 Codex 本身的默认设置。

**用 API 玩**：同样从 `开始游玩.cmd` 打开，在设置里换成“OpenAI 兼容 API”，填接口地址、模型名和密钥即可，存档照样写硬盘、和本机 ChatGPT 模式是同一份。直接双击 `index.html` 也能用 API，但存档只在浏览器里。

说书人有三种接法，在游戏的 **设置 → 说书人接口** 里切换：

1. **Claude（claude.ai 内）**：在 claude.ai 以 Artifact 打开时，游戏通过 `sample` 能力调用 Claude，消耗你自己的 Claude 额度，不需要密钥。
2. **OpenAI 兼容 API**：用浏览器直接打开 `index.html`，或部署到 GitHub Pages 后，填入接口地址、模型名和 API 密钥即可。GPT、DeepSeek、Kimi 等兼容 `/chat/completions` 的服务都可以用。密钥只保存在你自己的浏览器里。
3. **ChatGPT（本机）**：从 `开始游玩.cmd` 打开的本机页面使用；账号授权由本机 Codex 管理，网页不接触账号令牌。此模式消耗账号套餐额度，不是离线模型。

本机模式的存档写在硬盘的 `.dragon-oath-local/saves/` 里（浏览器里另有一份副本），换浏览器、清理浏览器数据都不会丢，覆盖前还会自动留历史备份。claude.ai 和直接打开文件时，存档只在浏览器里。不同入口之间、换电脑时，用存档菜单里的“导出当前进度”和“从文件导入”搬存档。详细接入与实测范围见 `HANDOFF.md` 的“本机 ChatGPT 接入”。

开启 GitHub Pages：仓库 Settings → Pages → Source 选 `main` 分支根目录，保存后就能通过 `https://<用户名>.github.io/dragon-oath/` 访问。

## 给后续开发者

整个游戏是 `index.html` 一个文件，原生 JS，不用构建，也没有依赖。开发前先读 `docs/剧本设定集.md`，所有剧情和数值都以它为准。

核心原则：**代码管数字，AI 管故事**。AI 每轮返回“叙述正文 + `@@@` + JSON 变更请求”，由 `applyGM()` 校验后才生效（赞同度单轮 ±15、金币 ±50、标记只接受 `FLAG_KEYS` 里的键等）。

| 代码位置 | 作用 |
| --- | --- |
| `RACES` `CLASSES` `BACKGROUNDS` `SKILLS` | 角色创建数据。仿 BG3：选职业时 `classPreset()` 套用该职业的推荐属性（`CLASSES[x].base`，都是 27 点）；种族加值 +2/+1 由玩家自选（`draft.bonus`，默认放在 `CLASSES[x].prime` 两项），种族只决定特性；背景只给技能 |
| `COMPANIONS` `PEOPLE` | 同伴角色卡与立绘 id |
| `SCENES` `nextAct()` | 场景锚点：每场必然发生什么、能推进到哪些场景；一幕结束后的卡片按钮进入下一幕 |
| `FLAG_KEYS` | 允许写入的世界状态标记及取值 |
| `SYSTEM` `buildPrompt()` | 说书人提示词与每轮上下文 |
| `rulesBlock()` | 玩家在设置里写的“给说书人的额外要求”：通用要求存在浏览器（`pref.rules`），这一局的要求跟着存档（`state.rules`），排在系统规则之后，只管怎么讲故事，不能改规则、数值、输出格式和尺度 |
| `narrate()` | 说书人接口：换模型只改这里 |
| `applyGM()` | 校验并执行 AI 的 JSON |
| `openDice()` `finishRoll()` | d20 检定 |
| `KITS` `FEATS` `ENEMIES` `ENCOUNTERS` | 战斗数据：职业武器与特技、敌人数值、遭遇（区域、敌人、事件） |
| `startCombat()` `advanceCombat()` `endCombat()` | 区域制回合战斗：开战、回合循环、结算 |
| `foeTurn()` `allyTurn()` | 敌人和同伴的自动行动 |
| `applyCombatFx()` `combatBrief()` | 即兴行动效果的校验执行、给说书人的战况 |
| `renderCombat()` | 战斗面板 |
| `recentLines()` `remember()` `summarize()` | 记忆：最近剧情原文、角色记忆、后台整理前情提要 |
| `levelUp()` `growth()` `applyAsi()` | 等级：里程碑升级、职业随等级成长、属性提升 |
| `ROMANCE` `CAMP_EVENTS` `applyBonds()` | 恋爱阶段、营地夜谈的处境素材、恋爱/关系/补给字段的校验 |
| `enterCamp()` `talkTo()` `restNight()` `renderCamp()` | 营地：扎营、找人夜谈、睡觉长休与共度一夜、营地面板 |
| `newGame()` `save()` `diskInit()` | 存档：浏览器 localStorage 一份，本机服务上再写硬盘（`/__save/*` 接口，见 `local-server.mjs`）；导出 / 导入 |

加新的一幕：在 `SCENES` 里追加场景（写 `act: n`）、在 `FLAG_KEYS` 里登记新标记、在 `COMPANIONS` 里加新同伴（写 `act: n`，之前的幕里不出现），在 `ACT_NAMES` `END_TEXT` 里补上幕名和结束语，再给上一幕最后一场写 `after: "新场景 id"`。需要升级的场景写上 `level: n`（进入这一场时全队升到 n 级）。

### 场景怎么组织

- 场景字段：`next` 可以是一个 id，也可以是数组（多个出口）；`gate: { 场景id: () => 条件 }` 控制某个出口什么时候能走；说书人只能 `advance` 到 `next` 里、且满足条件的场景。
- `recruit`：这一场可以招募谁（序幕的袭击和余烬是四位老同伴，第一幕开场和港口是米拉/奈雅，废塔是莉拉，码头可以把序幕离开的维克斯劝回来）。`meet`：这一场在场但还没入队的同伴；`meetIf` 给某个同伴加出场条件（港口枢纽的维克斯要等债有了结果才会来酒馆，之后可以在这里劝他入队）。`rescue: true`：序幕被交给教团的同伴关在这里，可以救回。
- `alone: true`：没有同伴在场（梦境）；`dream: true`：可以改赫斯提雅的信任。`endAct: n`：这一场 `scene_end` 后第 n 幕结束，弹出结束卡片；`after` 是卡片上“进入下一幕”去的场景。`endNeeds: { flags, turns }` 要求指定标记已写入、玩家在本次场景中至少回应指定次数，且没有待掷的检定，才能结束。
- `goals: [{ flag, name }]`：本幕目标及对应标记，日志显示进度和核对入口，枢纽侧栏显示完成情况。`jail: true`：这一场可以探望关押在酒馆地窖的同伴；被关押者不会入队、参战或出现在营地。
- **地点 = 入口 + 小场景**（10-28 起，仿 BG3 一个地点里有好几处可以逛）：入口场景带 `loc1`/`loc2`（算升级的地点），里面的小场景之间、和入口之间可以来回走，也能直接回枢纽；小场景可以用 `gate` 加条件。第一幕：码头 = 码头 / 金鳗赌场 / 地下斗兽场 / 金鳗的货舱（知道债才找得到）；废塔 = 塔楼 / 地下室（暗门通下水道）；沉船湾 = 龙尸 / 礁缝与沉船；总督府 = 白天 / 月光舞会（要请柬）/ 金库；下水道 = 迷宫 / 地下祭室；另有不算升级的鱼市与灯笼街（买东西、接支线）。第二幕：骨骼岛 = 沙滩 / 头骨洞穴；烬火岛 = 前哨 / 导师的书房 / 熔炉厅；雾隐岛 = 渔村 / 纪念礁（伊芙）；神殿 = 勇气 → 真相之厅 → 誓约之心（前一重试炼的标记写好才能往里走）。第三幕：被围的港口 → 先救的街区（三选一，`act3.saved_first` 决定能去哪个）→ 避难所（枢纽）⇄ 被围的街巷 / 战争会议 → 最后一夜 → 山脚 → 三条路各一场（`act3.route` 决定）→ 祖坛 → 烬王。
- **支线**（`SIDE`）：`goal` 是给说书人的完整做法（可以写答案），`task`（可选）是任务日志里给玩家看的目标，没写就显示 `goal`，标记名会被去掉。`at` 是能接的场景，状态写在 `side.<id>`：`taken` 接下、`done` 完成、`failed` 失败。代码只管顺序（先接下才能完成或失败，完成后不能改）和发奖励（`gold`、`supplies`、`items`、`flags`）。`need` 是可选的前置条件，用来串 NPC 事件链（玛莎、小汤姆、萨丝、伊芙、老鳗各 3 步，后一步要前一步 `done`）。提示词里列出这一场能接的支线（`hook`）和所有进行中的支线（`goal`、奖励），日志里有“支线”一栏。有的支线会影响第三幕：结界石让学院残部成为盟友，亡灵骑士的剑让潮裔成为盟友（没被武力得罪时），老鳗的最后一笔让黑潮会成为盟友，伊芙的信可以代替她的证词去说服主教。现在第一幕 14 个、第二幕 12 个、第三幕 13 个。
- **神殿试炼素材**（`TRIALS`）：`fears[玩家背景]` 给勇气试炼的幻象和过关办法，`secrets[同伴]` 给真相之厅的拒绝理由/说服方式和两层秘密，`trialLine()` 只在 `act2_temple`、`act2_temple_truth` 把对应的素材拼进提示词；赛勒涅不在这里说破容器，奈雅不在这里交出真名。
- 第一幕是**枢纽 + 地点**：`act1_1` 开场 → `act1_hub`（灰帆港，在醉龙酒馆睡觉不耗补给）⇄ 五个地点（`loc1: true`，任意顺序、可以反复去）→ 拿到航海图和船（`act1.chart`、`act1.ship`）后才能去 `act1_lighthouse` → `act1_dawn` 结束。
- 航海图封在酒馆地窖“龙息”酒桶底下，要用守誓人的钥匙才能打开：`act1.key` 记钥匙怎么拿到的（偷、揭发后合法取回、勒索），回地窖打开暗格后 `act1.chart = opened`。没有钥匙时说书人写 `act1.chart` 会被丢弃；旧存档里 `act1.chart` 记的是拿法，读档时自动补上同值的 `act1.key`。
- `act1.hostage` 记录灯塔的人质；`act1.ship` 记录取得的船，`act1.ship_intact` 记录是否受损，`act1.departure_ship` 单独记录实际出海的船（`fishing` 是民用渔船），避免原船损坏后丢失航线选择。
- 反复去的场景每次单独写一章纪要（记录条目带 `v`，章节标题写“（第 2 次）”）。
- **场景推进的保险**（10-29～10-30，完整通关里反复出现“叙述到了别处、场景没切”和“该推进时说书人不写 advance”，所以把关键推进收回代码）：
  - `route(sc, id)`：枢纽（`hub`）可以直接去地点入口（`loc1`/`loc2`）里面的小场景，先经过入口（算走过这个地点），两边的 `gate` 都要满足。枢纽的提示里由 `hubLine()` 列出这些小场景和那里能开的遭遇（写成“id「名字」（在哪几处）”）。
  - 在枢纽写了别处的遭遇 id 作为 `combat`，程序把场景带到有这个遭遇的地方再开打（按叙述的地点挑）。遭遇可以写 `after: 另一个遭遇`，要先打过那一场才能开（`docks_ship` 要先打过 `docks_brawl`）。
  - `walkTarget()`：说书人写了新 `location`、没写 `advance` 时，地点名（`loc` 的最后一段）对得上一个现在能去的地方，就跟过去。只认“地方”（`isPlace`：枢纽、地点入口和入口里的小场景，以及写了 `walk: true` 的场景，比如第三幕的街巷），灯塔、神殿这类剧情场景不会被走进去。
  - 场景可以写 `doneWhen: () => 条件`：条件成立后，玩家再回应一次，说书人还没写 `advance` 就自动去 `next` 的第一个（神殿最深处打完主教、第三幕救火街区打完黑龙幼体、冲锋和隧道打完山坡、祖坛打败或说服主教）。
  - `fightAfter: n`：玩家在这一场回应满 n 次，说书人还没写 `combat`，就由程序开这一场的遭遇（烬王）。进烬王那一场时（`enter: "altarRescue"`），还锁在石柱上的同伴会被救回队伍：神殿里被主教掳走的，和序幕里被玩家交给教团的都算。
  - 第一幕航海图和船都到手后，睡下就进灯塔之夜（`campNextOf`）。
  - 同一场玩家回应满 10 次，提示里提醒说书人该推进了。枢纽、营地和写了 `long: true` 的场景（神殿两重试炼、战争会议，本来就要很多轮）除外。
- 第一幕等级：每走完两个地点升一级（2 → 3 → 4），灯塔之夜 5 级（`levelNeed()`）。
- 维克斯的债：进入第一幕时记下 `state.act1Day`，倒计时始终按长休推进；知道债务后写 `act1.debt_known=true` 才在侧栏和任务日志显示。睡满 3 晚未解决时写 `act1.lise=sold`、维克斯 −30 并记忆，维克斯死亡则倒计时停止。
- 奈雅：身份暴露前叫“米拉”、用 `naia_disguise.webp`；说书人写 `act1.naia_exposed=true` 后叫“奈雅”、用 `naia_true.webp`。`act1.naia_fate` 由代码执行：`killed` 死亡、`imprisoned` 关押（`jailed`）、`recruited` 释放并入队。旧存档的关押状态自动转换。
- NPC 说明在 `NPC_NOTES`，按幕给说书人（第一幕加了老鳗、总督、萨丝、千面母；第二幕加了达林、奥斯瓦尔德、瑟拉长老、伊芙、主教瓦尔多）。
- 第二幕是**航程 + 枢纽 + 三座岛 + 神殿**：`act1_dawn` 的结束卡片进入 `act2_1`（出海，6 级）→ 每睡一晚一个海上事件：进入第二幕时 `voyagePlan()` 从五个事件（`act2_siren` 海妖之歌、`act2_ghost` 幽灵船、`act2_doldrums` 无风带、`act2_castaway` 漂流者、`act2_whales` 银鲸）里抽两个存进 `state.voyage`，最后一夜固定是 `act2_storm` 暴风（场景写 `voyage: true`，睡醒去哪一场由 `campNextOf()` 决定；旧存档走过的事件排在前面）→ `act2_hub`（锚地，睡觉不耗补给）⇄ 三座岛（`loc2: true`：`act2_bone` 骨骼岛、`act2_ember` 烬火岛、`act2_mist` 雾隐岛）→ 拿到神殿钥匙（`act2.temple_key`）后才能去 `act2_temple`（9 级）→ `act2_end` 结束。第二幕每走完一座岛升一级（6 → 9）。
- 场景进入时的代码结算（只在第一次进入时）：`saves: { ab, dc, text, fail }` 全队各掷一次属性豁免（海妖之歌）；`roll: { skills, dc, flag, ok, bad, text }` 由队里最擅长的人掷一次检定并写进标记（暴风：渔船出海有劣势，失败补给被卷走 2 份）；`enter` 调用 `SCENE_ENTER` 里的函数（神殿之后：誓约之心没处置就记为被主教抢走，主教掳走在队同伴里赞同度最高的人，写 `act2.taken` 并把他标成 `taken`，第三幕可以救）。结果写进系统记录，说书人照着写。
- 第三幕：`act2_end` 的卡片进入 `act3_1`（被围的港口，10 级，先救哪片街区 `act3.saved_first`）→ `act3_council`（战争会议）→ `act3_whisper`（最后一夜：进入时 `SCENE_ENTER.emberWhisper` 让赞同度 < 0 且个人任务没了结的同伴背叛离队，`c.betrayed`；营地睡下进入攻山）→ `act3_climb`（11 级，路线 `act3.route`：charge 要 ≥ 2 方盟友、tunnel 要奈雅双面间谍或放过鼠王、wings 要龙化值 ≥ 80，不满足的丢弃）→ `act3_altar`（救回被掳的同伴；说服主教 `act3.valdo=convinced` 要有伊芙的证词和骑士团日记）→ `act3_king`（12 级，烬王）→ `act3_end` 终章。
- 盟友（`ALLIES`）由代码按阵营声望和之前的标记算出，第三幕每轮在【世界标记】后面列给说书人：港卫军、总督私兵、黑潮会、学院残部、潮裔、达林、鼠王。
- **烬王三阶段**：生命 > 2/3 陷在火山口，爪尾三击加低语；之后升空吐酸，盟友各压制一次；支援用尽后烬王每隔一轮俯冲、可用近战攻击。降到 1/3 坠落到火山口边缘（`u.fallen`），之后每回合崩掉一块平台（`collapse()`：里面的人受 4d6、被甩到相邻区域，至少留两块），玩家的动作里多出“★ 最终抉择”，随时可以按下结束战斗；打到 0 也进入最终抉择。
- **主教的献祭**：主教生命过半开始献祭仪式，3 回合后若他还在场、没被即兴行动打断（`stops.ritual`），写 `act3.ritual=true`，烬王的生命上限 ×1.25。
- **重新挑战**：进入攻山那一场时，把当前进度存进浏览器的 `dragon-oath-checkpoint`；“港口陷落”的结局卡片上有“重新挑战（回到攻山之前）”，恢复后立即保存。
- **结局**（`ENDINGS`）：烬王坠落后玩家按下“最终抉择”或把它打到 0 时战斗停下（`c.end = "final"`），弹出最终抉择，七种结局里不满足条件的灰掉并写明缺什么（`need()`）；选定后写 `act3.ending`（说书人写的会被丢弃），进入终章，说书人按结局和每位同伴的个人任务、赞同度写尾声。最终战全队倒下，或从平台边缘确认撤退，进入“港口陷落”。没做完的抉择会一直在选项里提醒。
- 第二幕的标记：代码结算的 `act2.storm`、`act2.taken`、`act2.darin=woke`（战歌唤醒）说书人写了会被丢弃；`act2.egg_warmed` 是计数（规则 `"count"`，每次只能 +1，最多 3，维克斯还带着龙蛋时才算）；`act2.sacrifice=draconic` 扣 20 点龙化值（不够不能选）；`act2.heart=player` 加 30 点龙化值，`destroyed` 要潮裔是盟友（`act2.tideborn=ally`），`cult` 只由代码写。

### 等级怎么运作

- **里程碑升级**：不攒经验。场景数据写 `level: n`，进入这一场时 `levelUp(n)` 让全队升到 n 级；序幕“第一个梦”是 2 级。同伴始终和玩家同级（`state.player.level` 就是全队等级）。旧存档读档时 `catchUpLevel()` 按走过的场景补级。
- **每升一级**：生命上限 + 生命骰一半 + 1 + 体质调整值（取平均，不掷骰），全队回满。熟练加值 1–4 级 +2、5–8 级 +3、9–12 级 +4，影响检定和攻击。
- **属性提升**（4、8、12 级）：玩家在弹窗里给一项 +2 或两项各 +1（单项最高 20），体质调整值变化会按等级补生命上限；没分配完时选项里一直有提醒。同伴自动给主属性 +2，存在 `state.companions[id].ab`，读取属性统一用 `abOf()`。
- **职业成长**（`growth()`）：偷袭每 2 级 +1d6；戏法 5 级起伤害骰翻倍；魔法飞弹、治疗之语、至圣斩每 2 级多一次，其他特技 5 级多一次；战士、圣武士、游荡者 5 级“额外攻击”（玩家攻击后还能再攻击一次，同伴自动打两次）；法师 5 级学会火球术（选一个区域，里面所有人 8d6 火焰伤害，敏捷豁免减半，同伴也会被烧）。
- **6 级以后的职业能力**（`CLASS_FEATS`，`featsOf(kit, 等级)`）：战士 6 动作如潮（每场一次多一个动作）、11 三连击；圣武士 6 守护灵光（同区同伴 AC +1）、11 光耀打击（近战 +1d8）；游荡者 7 反射闪避（范围伤害减半）、9 直觉闪避（每回合第一次被命中伤害减半）；游侠 6 原野行者（AC +1）、9 齐射（向一个区域每个敌人各射一箭）；法师 9 冰锥术（区域 8d8）、11 火球每场两次；牧师 6 群体治疗之语、9 神圣打击（近战 +1d8）；术士 6 暗影步（瞬移到任意区域）、9 痛苦魔能（魔能爆加魅力）；吟游诗人 6 激昂之歌（全队命中 +2，2 回合）、9 群体治疗之语。同伴按各自的职业也有这些能力，自动战斗会用。
- **同伴专属技能**（`SIGNATURE`，每场一次，自动使用）：赛勒涅圣疗（救起倒地或重伤的同伴，恢复等级 × 3）、维克斯诡计（目标露出破绽，全队攻击它有优势）、卡西安祈福术（全队命中 +2，3 回合）、博林狂战怒吼（伤害 +3、受伤减半，3 回合）、莉拉奥术爆发（没有自己人的区域 4d8 必中）、奈雅形变（敌人认不出她，下一击有优势，攻击后现形）。
- **短休**：战斗外的选项“短暂歇脚”，每人恢复一半已损失的生命（至少等于等级），两次长休之间最多两次，不花补给、不推进天数、不找说书人。职业特技仍然按每场战斗恢复。
- 敌人不随等级变化，每场遭遇按设计等级写数值；第二、三幕的遭遇按幕整体加强（`SCALE`，个别再用 `SCALE_FIX` 调），因为队伍到那时有了装备、印记、职业能力和专属技能。

### 营地与恋爱怎么运作

原则是**自由优先**：台词和情节全交给说书人，代码只守几条底线。

赞同度除了说书人每轮给的，还有三笔由程序固定加（10-30 实测后加）：营地里陪一位同伴聊过一阵 +5（`endTalk`，玩家至少回应过一次才算，群戏和对手戏不算）、个人任务每完成一步 +7、每走完一幕队里的同伴 +7（`nextAct`）。数值在 `TALK_BONUS` / `QUEST_STEP_BONUS` / `ACT_BONUS`。

- **扎营**：战斗之外选“扎营休息”（消耗 1 份补给，`state.supplies`，新游戏 2 份；说书人可用 `supplies` 字段加减），或说书人在玩家想睡觉时写 `"camp": true`。场景可以写 `camp: false`（不能扎营）、`campFree: true`（不耗补给，比如序幕的酒馆）、`campNext`（睡醒后进入这一场）。序幕“余烬”打完仗睡觉时，先在壁炉边度过一夜，睡下后进入“第一个梦”。
- **夜谈**：营地事件现在有 93 个：每位同伴一个恋爱关键场景（见下面），每位同伴友情、暧昧、告白、恋人各一段，个人任务推进后的夜谈（`kind: "quest"`），第二、三幕的深交（赞同 ≥ 50）和恋人的第二段，每位同伴第二、三幕各一段友情（赞同 ≥ 30），最后一夜每位同伴的告别和恋人最终场景（`kind: "farewell"`，见下面），海上和战火里的群戏，以及同伴两两之间的吵架和玩笑（15 对）。营地面板列出在营地的同伴。`planNight()` 每晚按“主线 > 恋爱 > 个人任务 > 友情”挑一个事件，对应的同伴标“！”；同伴之间的群戏（`kind: "banter"`）和最后一夜的告别（`kind: "farewell"`）另外列成按钮，不占“一个重要事件”的名额。事件（`CAMP_EVENTS`）只写**处境和可用的素材**，说书人可以不用，玩家也可以把话题岔开。说书人写 `talk_end` 或玩家点“结束谈话”就回到篝火边。营地里不推进主线、不开战。
- **恋爱**：阶段 `none → hint（暧昧）→ together（恋人）→ vowed（誓约）`，说书人用 `romance` 字段推进，**营地内外都可以**。代码只管：一次一格；赞同度门槛 25 / 40 / 50；誓约要先通过个人任务的考验（`c.tested`，见下面“个人任务”）；角色底线 `ROMANCE_RULES`（赛勒涅被发现撒谎就不接受；各人接受多人恋爱需要的赞同度）。分手写 `to: "none"`。
- **多人恋爱**：已有恋人时和别人走到恋人，这段关系自动记为秘密（`secret`）。现任会通过营地事件找你谈，用 `consent` 表态：同意后不再是秘密，不同意赞同度 −15。秘密恋情在其他恋人也在营地的夜里有三分之一的机会败露：所有恋人赞同度 −25，并记进角色记忆。
- **恋爱关键场景**（`love_*`，设定集各同伴“恋爱线”的关键场景）：营地事件 `*_scene` 带 `scene` 字段，玩家点“跟着去”就离开篝火，进入只有两人在场的小场景（场景写 `with: 同伴 id`），说书人写 `scene_end` 后回到篝火边，营地状态原样恢复，还能找别人聊或睡觉。赛勒涅月下练剑、卡西安海边篝火、博林屋顶醉谈、莉拉深夜研究在赞同 ≥ 40、没恋爱或暧昧时出现；维克斯屋顶烟火在赞同 ≥ 55 的暧昧或恋人阶段；奈雅“哪一张脸”要身份暴露、赞同 ≥ 50。
- **最后一夜的告别**（`kind: "farewell"`）：只在 `act3_whisper`，每位同伴一段普通告别（`!isLover`）和一段恋人最终场景（`isLover`）互斥；像对手戏一样列成按钮，不占“一个重要事件”的名额，所以一晚可以听完好几个人的告别。结局尾声素材在 `EPILOGUES`，`epilogueNote()` 按结局、恋人、个人任务抉择、死亡/背叛/被困把要点拼进终章提示，说书人按实际剧情改写。
- **插曲场景**（`interlude: true`）：从营地或长休进入的单独小场景，`enterInterlude(id, back)` 记下原来的场景、地点和营地，`scene_end`（满足 `endNeeds.turns`）时 `leaveInterlude()` 带回去；回来算新的一章。恋爱关键场景和赫斯提雅的梦都用它。
- **赫斯提雅的梦**（`hestia_dream1/2/3`）：序幕的第一个梦之外，每幕在长休时入梦一次（`dreamDue()`）：第一幕从第二晚起，第二幕上过一座岛之后，第三幕第一次在避难所睡下或者最后一夜（梦完直接进入攻山）。场景的 `trust: { high, mid, low }` 按信任 ≥ 20 / 中间 / ≤ −20 由代码选一段写进提示词（`dreamLine()`）；信任 ≥ 20 醒来给 1 点灵感。梦是插曲，醒来后代码接着让说书人写清晨（`state.pendingWake`）。
- **睡觉**：长休全员回满、天数 +1。有恋人在营地时可以选“和谁一起睡”，说书人写这一夜的亲密（到最亲密那一步用转场带过）和第二天清晨。
- **同伴之间**：`state.rel` 记两两关系值，说书人用 `relation` 字段调整（每次最多 ±10），提示词里会带上。
- **亲密的尺度**写在 `SYSTEM` 里：随关系阶段递进，双方都可以拒绝，每个同伴的方式不同。
- **个人任务**：数据在 `QUESTS`。每人两步加一个最后的抉择，每一步对应一个标记（第一步有的直接用剧情现成的标记，如 `act1.debt_known`、`act1.darin_axe`），抉择写 `quest.<id>`。代码只管：按顺序推进；第一步之后要赞同度 ≥ 20，≤ −20 拒绝个人任务；`act` 之前的幕不能做；抉择定了不能改（`questBlock()`，不合格的标记丢弃）。抉择的后果能由代码算的写在 `choice.on` 里（维克斯独自去交易：赞同 < 40 就带着妹妹和龙蛋消失）。说书人的同伴资料里带着进度和“下一步（别提前说破）”，日志里有“同伴的个人任务”。暧昧或恋人阶段的人另有一条“考验”（`test`），玩家做到时说书人写 `quest.<id>.tested=true`，记录会保留到确定关系之后，立誓约前仍需通过考验。第一幕能做的步骤写在场景锚点里：沉船湾（赛勒涅的日记）、码头（维克斯的龙蛋和抉择、卡西安的阿登与账本和抉择）、下水道（莉拉认出导师、博林得知达林活着）、灯塔（千面母握着奈雅的真名）；其余抉择在第二幕。

加新的战斗：在 `ENCOUNTERS` 里写区域（`adj` 是相邻区域下标，`tags` 可用 `cover` 掩体、`high` 高处、`obscured` 遮蔽、`exit` 出口）、敌人和回合事件（`spawn` 增援、`blast` 炸到所有人、`unless` 写在 `stops` 里的机关，即兴行动用 `"stop"` 阻止后就不触发，例如灯塔的导火线）；`startFlags` 可在开战时记录尚未写入的合法标记。新敌人加进 `ENEMIES`，再把遭遇 id 写进对应场景的 `encounters`。说书人只能开启当前场景登记过的遭遇；每场遭遇只打一次，打过的会在提示词里列为“已经打完”，再要动手就用检定或叙述（码头另有一场 `docks_ship` 强夺黑鳗号，给打完斗殴还想抢船的玩家）。

### 酒馆升级怎么运作

- 场景写 `tavern: true` 的地方（第一幕的灰帆港枢纽、第三幕的避难所）有“和玛莎商量修整酒馆”（玛莎死了是小汤姆），花金币升级（`TAVERN`），写进标记 `tavern.rooms` / `tavern.barmaid` / `tavern.intel`，说书人写的会被丢弃。
- 修缮客房（60）：在酒馆睡一晚，第二天可以短休 3 次。请吧女（40）：第一幕每在酒馆睡一晚 +8 金币，第三幕每晚补给 +1。地下情报站（120）：在酒馆和战争会议时提示词多一条消息（`INTEL`，按天数轮换，`intelLine()`）；第三幕攻山可以走熔岩隧道。
- 第三幕避难所的锚点按这三个标记写酒馆的样子。

### 阵营声望怎么运作

- 五个阵营（`FACTIONS`）：港卫军 `watch`、黑潮会 `tide`、旧学院 `academy`、潮裔 `tideborn`、灰烬教团 `cult`，−100 到 +100，分为仇恨、敌视、中立、友好、敬重。
- **声望 = 底数 + 增减**：底数由关键选择的标记算出（`FACTIONS[id].base(flags)`，例如和萨丝合作 +25、与黑潮会为敌 −40、先救哪片街区 +15，教团从 −30 起）；说书人用 `reputation` 字段写日常的小变化，每次最多 ±15、每轮最多 2 条，累计在 `state.repDelta`。关键抉择已经算进底数，说书人不用重复加。旧存档不用迁移。
- **影响**：商店（`SHOPS` 的 `faction`）敬重 8 折、友好 9 折、敌视贵 25%、仇恨不卖；第三幕的港卫军、黑潮会、学院残部、潮裔要声望 ≥ 20 才会来（`ALLIES`；达林、鼠王、总督私兵仍看标记）；烬冠加冕结局在教团声望 ≥ 0 时由主教亲自加冕，否则烬王只把你当工具。
- 说书人每轮在【世界标记】后面看到五个阵营的声望；日志里有“阵营声望”一栏，商店里显示该阵营的声望和折扣。

### 印记与龙化怎么运作

- **龙化值**（0–100）：玩家在 `state.player.draconic`，同伴在 `state.companions[id].draconic`。所有改动都走 `addDraconic(ref, n, notes)`：跨过门槛时提示解锁的能力；玩家跨过 40 / 60 / 80 时，在队的同伴按 `DRAGON_VIEW` 调整赞同度（莉拉 +3、奈雅 +1、维克斯 0、博林 −1、卡西安 −2、赛勒涅 −3）。说书人用 `draconic` 字段改玩家的；同伴的由代码改：进入第二、三幕各 +15，莉拉接受导师邀请 +30，用印记能力也会涨。
- **印记能力 `MARKS`**，每场战斗每种用一次，用一次龙化值 +cost：20 龙之眼（动作：伪装全部现形，本场全队远程无视遮蔽）；40 龙息（动作，选区域：(2 + 等级的一半)d6，敏捷豁免减半，DC 8 + 熟练 + 体质，会烧到同伴）；60 龙威（动作：所在和相邻区域的敌人失败就恐惧 2 回合）；80 龙翼（附赠动作：飞 2 回合，多移动一次、能飞到任意区域、不被借机攻击、近战够不着）。同伴自动战斗时会用龙之眼（有伪装时）和龙息（有个至少两个敌人、没自己人的区域时）。
- **共鸣与合体技 `COMBOS`**：同伴赞同度到 40 后，营地会安排一次“印记共鸣”（`kind: "resonance"`，排在恋爱之后、个人任务之前），两人看见对方最深的记忆；看过就写 `c.resonance = true`，解锁合体技（赛勒涅“晨星双剑”、维克斯“影中双刃”等）：和同区的那位同伴各攻击一次、都有优势、命中各加 2d6，每场一次。
- 说书人能看到玩家的龙化值和已解锁的能力，同伴资料里有他的龙化值、是否共鸣过、对玩家龙化的看法；侧栏显示龙化值和能力。
- 龙化值 40 / 80 的变体立绘：`portrait()` 按同伴的龙化值先找 `id_drac80.webp` / `id_drac40.webp`（排在表情差分前面，奈雅只在真身时用），没有图就照旧。六位同伴共 12 张变体已接入。

### 装备、商店和战利品怎么运作

- **物品表 `ITEMS`**：行囊（`state.player.inventory`，全队共用）里放的是名字，名字在表里的是真物品，不在的是杂物（说书人随手给的东西、职业自带的初始物品）。约 35 件：武器（近战/远程，`d` 伤害骰、`ab` 属性，`fin` 取力量敏捷较高者，`bonus` 命中和伤害、`extra` 额外伤害骰）、护甲（在原本 AC 上加）、饰品（`ac`/`hit`/`dmg`/`save`/`init`）、消耗品（`use.heal` 治疗、`use.blast` 扔向区域）。
- **装备栏**：每人近战、远程、护甲、两件饰品，存在 `state.gear[ref]`。角色卡里装上/卸下（战斗中不能换），玩家和入队的同伴都能装。战斗单位由 `partyUnit()` → `gearWeapons()` 把装备套到职业自带的武器上：近战换掉第一把近战武器，远程换掉第一把非戏法的远程武器（没有就加一把，所以战士也能拿弓）。AC、命中、伤害、豁免（`bonusFor` 的 `save_*`）、先攻都会加上装备。
- **消耗品**：战斗中治疗药水是附赠动作，炸弹和卷轴是动作（选区域，走火球术的流程，`castFireball` 带 `pick.item`）；同伴生命低于 30% 时会自己从行囊里拿药喝。战斗外在角色卡里给谁喝都行。
- **商店 `SHOPS`**：按场景开（鱼市、赌场黑市、船上补给、潮裔、避难所黑市），选项里有“逛逛……”；`mult` 是价格倍数，卖出半价，有的店也卖补给。
- **战利品 `LOOT`**：每场遭遇打赢后由代码发金币和物品，只发一次，写进战斗摘要给说书人。支线奖励的物品也在表里。
- **说书人给东西**：`items_add` 照旧能给杂物；表里标了 `rare` 的好东西，只有这一场的锚点里写着它的名字才算数（例如金库里的银刃匕首、黎明玛莎给的守誓人徽记），否则丢弃。
- 还没做：阵营声望影响价格（阶段 4）；战斗模拟还没给队伍配装备，第二、三幕的平衡要在阶段 3 一起重调。

### 战斗怎么运作

- 说书人在 JSON 里写 `"combat":"遭遇 id"` 开战。之后代码接管：先攻、移动、攻击、伤害、倒地与死亡豁免、借机攻击，以及敌人和同伴的行动。
- 玩家每回合有动作、附赠动作、移动各一次，在区域图上点选。自由输入框变成“即兴行动”：说书人裁定，可以先要求检定，再用 `combat` 字段给出伤害、状态、点火或敌人投降，由 `applyCombatFx()` 校验（单次最多 4d12、目标必须在场）。
- 轮到玩家前，说书人把这段时间的战况写成一段描写（设置里可改成“只在关键时刻”）。战斗结束时，代码把结果摘要发给说书人，由它接着讲故事、推进场景。
- 遭遇的 `bout: true` 是拳赛（斗兽场黑拳）：`boutRules()` 把全队换成拳头（1d6 + 力量），不用法术、职业特技、专属技能、印记和合体技，被打到 0 就出局（`out: "ko"`），不进入倒地和死亡豁免；接了支线 `side.arena_champion`（讲好规矩）就不触发第 3 回合放鳄鱼的事件（`unless: "fair"`）。
- 遭遇的 `lethal: false` 表示不会死人：死亡豁免失败三次只会昏迷。
- 第三幕的敌人字段：`breath: { dice, every, dc, n }` 每隔几回合向人最多的区域吐息（敏捷豁免减半）；`drain: { dc }` 每回合抽取一名持有者的印记（体质豁免，失败“失神”一回合，玩家龙化值 +10）；`king` 是烬王的阶段（`kingTurn()`）：生命 > 2/3 时爪尾三击加低语（感知 DC 16 失神），之后升空（`aloft`，近战够不着），每回合吐酸，盟友每方能把它压下来一轮（`grounded`）；没有剩余盟友支援时，每隔一轮自己俯冲进入近战范围。“失神”（`cond.stunned`）的人这一回合什么也做不了。
- 第二幕的敌人字段：`weak`/`immune: "fire"` 火焰伤害加倍/免疫（龙骨妖怕火，烬卫火焰免疫）；`burrow` 身边没有目标时从地下钻到任意有目标的区域；`frenzy` 生命低于一半后每回合多打一次；`object` 是不会攻击的物件（熔炉），不计入胜负；`mend: { type, n }` 每回合给同场某种敌人回血。遭遇字段：`wake: { who, target, ab, dc, need, flag, value }`——指定同伴每回合用动作唱歌（博林的铁炉堡战歌，魅力 DC 15），累计成功够了目标就醒来退场、写标记；`flee: { type, at, text }`——某个敌人生命掉到这个比例就逃走（雾海巨妖打掉一半就沉回海里）。
- 狂信徒濒死会对同区造成 1d6 火焰伤害；被这次自爆烧死的狂信徒不会再次自爆。开启“留活口”后，全队的近战可以活捉敌人。
- 敌人的 `multi` 是每回合攻击几次（卫队长、溺死水手、黑鳗号水手长）。
- 点燃的机关：回合事件写 `lights`（灯塔第 4 回合的导火线），战斗在它炸之前结束时由 `leftover()` 收尾：还剩 2 回合以上就扑灭；只剩 1 回合由敏捷最好的人掷 DC 15，失败照样炸（生命最低剩 1）；撤离或全队倒下则人走后它照样炸。结果写进战斗摘要交给说书人。
- 千面母（`shift: 15`）：开战时伪装成队伍里的某人（`u.guise`），看不见就打不到，同伴也不会选她当目标。玩家用动作“识破伪装”（察觉 DC 15），同伴没有可打的目标时也会去找；奈雅在场时自动认出养母。被识破后到她下次行动前，攻击她有优势。她伪装时的回合会贴近一人偷袭（优势 + 偷袭骰），然后现形。一次受到 15 点以上伤害、还没死，就换一张脸、换个区域重新躲起来。
- 分头行动：场景的 `split`（现在只有灯塔之夜）。说书人请求开战或离开这一场时，如果还没分组，先弹出“分头行动”让玩家选谁去另一边（也可以随时点“分派队伍”）。另一边由 `resolveSplit()` 结算：先挨看守的打（1 人 4d6、2 人 3d6、3 人以上 2d6，最低剩 1 点生命），再由组里智力或敏捷最好的人拆炸药（DC 15，两人以上优势），失败每人再挨 1d6；结果写进 `split.flag`（`act1.ship_intact`）。分组前说书人写这个标记会被丢弃。去了另一边的人这一场不算在场（`present()`），不参战；下一场自动回来。

### 记忆怎么运作

每一轮都是一次独立的请求，提示词从存档重新拼出来，不会越聊越长。为了让角色记得更早的事，记忆分五部分，都存在 `state.memory` 里：

- **最近剧情**：还没压缩的原文，最多约 1.2 万字。战斗流水账不算在内（只在战斗中附带最近 10 条），战斗结束后由一条结果摘要代替。
- **往事**（`memory.chapters`）：每条记录都带场景标记 `s`。一个场景结束后，`writeChapter()` 在后台读这一场的全部原文，写一份 250–400 字的章节纪要，写好就不再改，所以早期细节不会在反复改写中走样。旧存档会按记录里的章节标题补上场景标记，并每轮补写一章。
- **前情提要**：原文攒到 1 万字时，`summarize()` 在后台把较早的部分（只留最近 5000 字原文）交给 AI 压缩进提要，被压缩的条目打上 `m` 标记。提要只管往事还没覆盖的部分，往事写好后会自动瘦身。
- **角色记忆**：每人最多 10 条“关于你的事”。说书人遇到承诺、谎言、恩情、亲密时刻等，用 JSON 的 `remember` 字段当场记下，屏幕提示“某某会记住这件事”；整理提要时 AI 会合并去重。玩家可以在日志和同伴的角色卡里看到。
- **想起的旧事**：`recallLines()` 把玩家这句话切成 2–4 字的片段，在已压缩（`m`）的旧原文里查找，越少见的片段权重越高、人名加倍，取最相关的 3 段（连同当时玩家说的话，最多 2500 字）交给说书人。纯文本匹配，不调用模型。

后台的章节纪要和前情提要排成一队依次执行（`queueMem()`）。本机 ChatGPT 一次只接一个请求，所以这个模式下玩家行动会先等队里的任务做完。

阈值在 `RECENT_CHARS` `SUM_AT` `SUM_KEEP` `CHAPTER_SRC` `RECALL_CHARS` `RECALL_MIN` 几个常量里，调大能记得更多原文，但每轮更费额度。往事每章约 400 字，三幕全部写完大约 1 万字；到时可以考虑把一整幕的纪要再合并成一段。
