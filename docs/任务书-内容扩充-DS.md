## 写作要求（BG3 风格）

- 用简体中文写，和现有条目的语气一致：具体、有画面、有人物性格，不写空话。
- **每件事至少两种解法**：打、谈、偷、骗、绕开都行，写出检定和 DC（常用 DC 13～17）。
- **选择有代价**：帮了一方就可能得罪另一方；同伴会表态（写清楚谁赞同、谁反感，参考设定集里每个同伴的“赞同 / 反感”）。
- **不要和主线冲突**：不能替主线做决定、不能杀掉主线 NPC、不能提前揭开秘密（赫斯提雅想借宿主重生、赛勒涅是容器、达林还活着等，见设定集“只对 GM 可见”的部分）。

## 任务 D1：第二、三幕的支线

现在第一幕 10 个、第二幕 5 个、第三幕 4 个。**第二幕加 5 个，第三幕加 5 个。**

数据在 `index.html` 的 `const SIDE = {`，照现有条目的格式加：

```js
  some_id: { name: "支线名", act: 2, at: ["act2_mist", "act2_hub"],
    need: () => state.flags["act2.murals"] === true,   // 可选：满足才出现
    hook: "接任务时的处境：谁、为什么找你们、说了什么（给说书人看的，一两句）",
    goal: "怎么完成：去哪个场景（写场景 id）、几种解法和检定 DC、可能的失败",
    reward: { gold: 40, supplies: 1, items: ["物品名"], flags: { "某标记": 值 } },
    rewardText: "玩家看到的奖励说明" },
```

- `id` 用小写英文和下划线，不能和已有的重复。
- `at` 只能用已有的场景 id（`SCENES` 里的键，第二幕 `act2_*`、第三幕 `act3_*`）。第三幕的支线大多应该从避难所 `act3_haven` 或街巷 `act3_streets` 接。
- `items` 只能用 `ITEMS` 里已有的物品名，或者不在表里的“杂物”（例如“一封信”）。
- `flags` 只能用 `FLAG_KEYS` 里已有的键和合法值（看 `FLAG_KEYS`、`QUESTS`、`SIDE` 的定义）。不要新造标记。
- 题材参考设定集，第二幕：海上、三座岛、潮裔、教团前哨、龙蛋、伊芙；第三幕：被围的港口、难民、各方盟友、背叛者、最后的准备。可以让支线影响第三幕的盟友：奖励里的 `act1.eel`、`act2.tideborn` 这类标记，或者完成的支线本身。阵营声望的底数会读一部分支线，见 `FACTIONS`。
