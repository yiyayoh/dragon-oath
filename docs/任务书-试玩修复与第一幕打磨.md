## 第一部分：试玩报告里的问题

### A1（P1）序幕结束得太早，跳过赫斯提雅的梦

**报告**：第四场睡觉时，说书人一次返回 `{"advance":"prologue_5","scene_end":true}`，旧代码先进入第五场，再用新场景判断结束，梦没出现就“序幕完”。

**现在的状态**：`applyGM()` 末尾已改成“先看 advance，没有 advance 才看 scene_end”，并且只有带 `endAct` 的场景能结束，所以**报告里这个组合现在不会再提前结束**。但还有一个漏洞：从营地睡下进入第五场时（`restNight()` → `goScene(campNext)` → `gm(...)`），说书人对梦的**第一条回复**里如果就写 `scene_end: true`，梦会在玩家开口前结束。`act1_dawn` 同理。

**怎么改**：
1. 给能结束一幕的场景加结束条件，写在数据里：
   - `prologue_5`：`endNeeds: { flags: ["prologue.hestia_answer"], turns: 1 }`
   - `act1_dawn`：`endNeeds: { turns: 1 }`
2. `applyGM()` 里接受 `scene_end` 前检查：`flags` 里的标记都有值；本场景（用 `curKey()`，因为场景可以重复进入）里玩家说过的话（`k === "you"` 的记录）不少于 `turns`。条件不满足就忽略这次 `scene_end`，`console.warn` 一下。
3. `nextLine()` 给说书人的提示里写明结束条件，例如“这一场要等玩家回应过、写好 prologue.hestia_answer 之后才能 scene_end”。
4. `SYSTEM` 的 advance 说明后加一句：`scene_end 只在【当前场景】写明“这一场结束时 scene_end 为 true”的场景使用，别的场景不要写。`（报告里第三场的回复也写过 scene_end。）

**验收**：用假说书人（见文末）跑三种情况：①第四场回复同时带 advance 和 scene_end → 进入梦境，没有结束；②梦的第一条回复带 scene_end → 不结束；③玩家回应一次、写了 hestia_answer 之后带 scene_end → 结束，弹出卡片。

### A2（P2）模型不支持被当成“网络中断”

**报告**：选了账号不支持的模型，后端返回 HTTP 400 / `model_not_found`，页面却提示“连接中断，请检查网络”。

**现在的状态**：`local-codex.mjs` 的 `classify()` 没认出这类错误，落到 `network`；`local-server.mjs` 的 `allowed` 白名单里也没有对应的错误码。另外 `narrateWithChatGPT()` 在玩家选的模型不在账号目录里时会**悄悄换成账号默认模型**，而默认往往是最贵的 Astra。

**怎么改**：
1. `classify()` 加一条：`/model_not_found|model is not supported|unsupported model|does not exist/i` → `new NarratorError('model_unsupported')`。放在 `network` 之前。
2. `local-server.mjs` 的 `allowed` 加上 `model_unsupported`。
3. `narrateWithChatGPT()`：玩家**明确选了**模型、但它不在目录里时，不要悄悄退回默认，直接抛 `model_unsupported`。没选（空字符串）才用账号默认。
4. `index.html` 的 `ERR` 加：`model_unsupported: "这个模型在你的账号或当前 Codex 版本里用不了。请在设置里换一个说书人模型（整理记忆的模型也检查一下），再点“重试上一步”。"`
5. SSE 的 `done` 事件带上实际用的模型名（`{ type: 'done', text, model: chosen }`），页面在状态栏显示“说书人：GPT-6.1-Sol”。
6. `tests/local-server.test.mjs` 加测试：假说书人抛 `model_unsupported` 时，页面收到同样的错误码；选了不在目录里的模型时返回 `model_unsupported`。

### A3 教团战的连锁爆炸

**报告**：同伴打死一个狂信徒，自爆 1d6 炸到同区其他狂信徒，接连爆炸，六个小怪一回合全死，同伴也被炸倒一片；“留活口”只管玩家的近战，同伴照杀。

**现在的状态**：`hurt()` 里狂信徒死亡时对同区所有人（包括其他狂信徒）造成 1d6 火焰伤害，被炸死的狂信徒会继续自爆，于是连锁。代码和报告一致。

**怎么改**：
1. **不连锁**：被自爆炸死的狂信徒不再自爆（`hurt()` 的 `o.fire` 来自爆炸时，把死亡标成“被烧尽”，跳过 `explode`）。传给 `hurt()` 一个 `o.blast: true` 来区分，不要影响烬火燃烧区域等其他火焰伤害。
2. **看得见**：战斗面板里狂信徒的单位卡加一行小字“濒死自爆：同区 1d6”（`renderCombat()` 里 `.unit .cd` 那一行，现在用来显示状态）。`combatBrief()` 里也写给说书人。
3. **留活口对全队生效**：`c.spare` 打开时，同伴的近战也活捉（`allyTurn()` 里传 `spare: c.spare` 给 `fightTurn()`，`attack()` 已经支持 `o.spare && !w.ranged`）。按钮说明改成“开启后，全队的近战把敌人打到 0 生命时会活捉而不是杀死”。活捉的狂信徒不自爆（现在的代码已经是这样，确认一下）。

**验收**：写个脚本把教团袭击自动打 200 局（见第二部分 B5 的模拟器），连锁爆炸改前改后各统计一次“第一回合内死掉的狂信徒数量”和“我方倒地人次”，把数字写进提交说明。

### A4 等待和模型不透明

**报告**：每轮 14–24 秒，检定要来回两次，转场还有章节纪要；玩家不知道在等什么、用的哪个模型。另外章节纪要的请求要求“只输出正文”，但本机桥接的 `baseInstructions` 强制“正文 + @@@ + JSON”，每次纪要都多生成一段 JSON。

**怎么改**：
1. 状态栏显示：正在等什么（“说书人正在构思……”/“正在整理记忆（后台）……”）、已经等了几秒、用的模型（A2 第 5 点）。等记忆整理时提示“先整理完上一章的纪要，马上就好”。
2. `/__gpt/narrate` 接受可选的 `mode: "memory"`（`index.html` 里 `narrate(..., { memory: true })` 的调用带上）。`narrateWithChatGPT()` 在 memory 模式下换一份 `baseInstructions`：只输出要求的内容（纪要正文或 JSON），不要 @@@。`local-server.mjs` 校验 `mode` 只能是 `"memory"` 或不传。加一项测试。
3. 页面里纪要的解析（`splitReply(out)[0]`）保留，兼容 API 和 Claude 模式。

### B5 第一幕的战斗难度没调过

**问题**：第一幕六场战斗的数值是照设定集填的，没跑过。下水道（5 个敌人含无面刺客）、灯塔（千面母 70 血 + 3 刺客）可能太难；这几场都会真死人，玩家倒下就是游戏结束。

**怎么做**：
1. 写一个**战斗模拟器**脚本 `tests/combat-sim.mjs`（Node 运行）：从 `index.html` 抽出 `<script>` 内容，在 `vm` 里跑，用最小的 DOM 桩（`document.getElementById` 返回假元素、`localStorage` 用内存对象），把 `narrate` 换成空函数、`sleep` 换成立即返回、`renderPlay` 换成空函数。构造一个状态：指定等级、四人队伍（玩家用一个常见职业，例如圣武士或盗贼，由同伴 AI `allyTurn()` 代打）、指定遭遇，跑到 `combatResult()` 出结果。每个遭遇跑 300 局。
   - 如果从 HTML 里抽代码太别扭，可以把战斗相关的纯函数挪到 `<script>` 里一个清楚的段落，但**不要拆文件**（游戏要保持单文件）。
2. 统计每场遭遇在**设计等级**下的：胜率、平均回合数、平均我方倒地人次、有人阵亡（`lethal` 场）的比例。设计等级：码头 2–3、废塔 2–3、沉船湾 3、总督府 3–4、下水道 3–4、灯塔 5。队伍按 4 人（玩家 + 3 同伴）算。
3. 目标：胜率 ≥ 85%；`lethal` 场有人阵亡的比例 ≤ 10%；平均 3–6 回合。不达标就调**遭遇**（敌人数量、起始区域），其次调敌人数值，不要改玩家和同伴的规则。改动和前后数字写进提交说明，结果表写进 `README.md`“战斗怎么运作”。
4. 把序幕教团战也跑一遍，对照 A3 修复前后的数字。
5. 模拟器加进测试说明（`HANDOFF.md`“怎么测试”），以后加新遭遇都跑一次。
