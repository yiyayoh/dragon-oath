## Bug、复现步骤与实际影响

### P1：进入第五场的同一个回复会直接结束序幕

复现：在第四场“余烬”决定睡觉或长休；真实说书人返回包含下列两个字段的 JSON。首轮和换 Sol 后均发生。

```json
{"advance":"prologue_5","scene_end":true}
```

预期：进入梦境，赫斯提雅出现，对话并记录 trust/question/refuse 后才结束。实际：scene 改为 prologue_5 后，程序立即读取同一回复的 scene_end，将 ended 设为 true；显示“序幕完”，自由行动入口消失。此时 hestia_answer 尚未写入，赫斯提雅没有出场。

原因核对：固定版 index.html:1311 先执行 advance；index.html:1319 用已经改变的 state.scene 判断是否可结束，没有校验回复所属的原场景或梦境关键事件。建议以后以转场前场景及梦境事件是否完成为依据校验结束条件；本次没有修代码。另在第三场到第四场的回复里也出现 scene_end=true，只因目的场景不是第五场而未造成结束。

证据：08-final-premature-end.json、09-ending-card.png、12-sol-premature-end.json、sol-events.jsonl。两次完整原始返回均可查。

### P2：模型不支持被显示成普通网络错误

复现：旧 npm 版连接明确指定 gpt-6.1-sol 或 gpt-6.1-terra，发出一轮真实行动。后端返回 model_not_found / HTTP400；页面显示“连接中断，请检查网络后重试”。反复重试没有帮助，也没有告诉玩家实际问题是连接程序/模型兼容。

建议：把模型不支持与网络中断分别处理，展示实际模型；选择失效时不要静默换成更费额度的默认模型。Claude 新版已经解决本机优先选择哪份 CLI 和模型可选的问题，本报告没有验证新版所有失败提示。错误证据为 sol-model-audit.jsonl、11-sol-model-rejected.png。

### 战斗体验：小怪连锁爆炸压倒了战术空间

本次第二回合，同伴击杀狂信徒触发大堂全区域连锁爆炸，六名小怪相继死亡；赛勒涅和博林倒地，玩家多次陷入濒死，最后靠半兽人特性、拉起与治疗恢复到4HP。战后赛勒涅1HP、博林1HP、卡西安7HP、维克斯7HP。最后术士成功投降，战斗结束。
