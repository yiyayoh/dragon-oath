## 要找的问题（按类别）

1. **引用了不存在的东西**：文字里写的标记（`act1.xxx`、`quest.xxx`、`side.xxx`）在 `FLAG_KEYS` 里没有，或者取值不对（比如写了 `act2.heart=given`，但合法值只有 hestia / player / destroyed / cult）；写的场景 id 不存在；写的物品名既不在 `ITEMS` 里，又像是要当装备用。
2. **时间线矛盾**：一件事在某一幕里被提到，但它其实要到更后面才会发生（例如第一幕的营地事件提到神殿里的事）；或者 `when` / `need` 的条件让事件出现在它的前提还没发生的时候。
3. **人物矛盾**：同一个人在不同地方的性格、经历、关系对不上（比如一处说维克斯的妹妹叫莉丝、十六岁，另一处说法不同）；NPC 死了以后还被写成会出现（例如老鳗被卡西安杀死后，还有支线让他出场，`need` 没有挡住）。
4. **泄露秘密**：在揭开之前就把“只对 GM 可见”的秘密写给了玩家能看到的地方，或者写在说书人会在揭开之前就拿到的素材里，而且没有写“不要说破”（赫斯提雅想借宿主重生、赛勒涅是容器、达林还活着、奈雅是间谍、总督受教团资助等）。
5. **规则冲突**：文字许诺了代码不会给的数值奖励（比如“补给 +3”写在 `goal` 里，但 `reward` 里没有）；或者支线奖励里的标记会意外改变主线（比如奖励直接写了某个阵营成为盟友，绕过了代码的条件）。
6. **重复**：两段营地事件、两条支线讲的几乎是同一件事。
7. **错字、病句、中英混杂**：简单列出来就行。

## 报告格式

按上面的类别分节，每条写：

- **位置**：数据块和 id（例如 `SIDE.eel_wreck.goal`、`CAMP_EVENTS.vex_act3_dull_blade.seed`、`SCENES.act2_mist.anchor`）
- **问题**：一句话说清楚哪里不对
- **依据**：对照的另一处原文（设定集的哪一段、另一个数据块的哪一句）
- **建议怎么改**：一两句

最前面写一段总结：读了哪些数据块、一共找到多少条、你觉得最严重的 5 条是哪些。拿不准是不是问题的，单独列一节“拿不准的”，不要硬算成问题。
